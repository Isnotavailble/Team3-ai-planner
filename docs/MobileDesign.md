# Lattice MSME — Design Specification v1

A mobile-first daily business companion for Myanmar small business owners. Owners feed the app via voice notes, text entries, PDFs, Excel files, Telegram, and Viber. The app extracts structured facts, builds a temporal model of the business, and surfaces a five-screen experience: a home briefing, a financial report, goals and budget tracking, an analytics deep-view, and a profile. The visual language is "Plum Linen" — a premium consumer-financial aesthetic adapted for business use, with disciplined accent usage and editorial typography.

**Status:** v1, locked against the build plan in `lattice-msme-build-plan.md`. This document specifies *what the user sees and inputs*. The build plan specifies *how to build it*.

## Part 1 — User and product premise

The user is a Myanmar small business owner running a shop, restaurant, services business, or trading firm. They run their business from a phone. They have 30–90 seconds of attention per app session. They speak Burmese primarily, may read some English. They are not analysts and not designers — but they are competent adults running real businesses, so the app must treat them as such. No condescension, no cartoon icons, no "wellness coach" tone.

The app answers four questions every time it opens: **am I making money, who hasn't paid me, what's running low, what's about to bite me.** Then it lets the owner go deeper.

The temporal knowledge graph engine (Zep) runs underneath, invisible. The owner does not see entities, edges, branches, or scenarios. They see numbers, charts, and cards.

## Part 2 — Input specification

Six input pipelines in v1. Each writes to the same fact-extraction layer, so downstream code does not know how a fact arrived.

### 2.1 Voice check-in (the primary input)

**What the user does:** Taps the dark mic button in the center of the bottom dock. Records 10–90 seconds in Burmese (or English, or mixed). Taps stop.

**What gets stored:** An audio file in Supabase Storage, a Burmese transcript via Whisper, an array of extracted facts pending confirmation.

**What gets extracted (the fact schema):**

```
fact = {
  type: 'sale' | 'payment_received' | 'payment_made' | 'expense' |
        'customer_visit' | 'customer_absent' | 'inventory_change' |
        'supplier_signal' | 'market_signal' | 'staff_event' |
        'decision_pending' | 'note' | 'other',
  amount?: number,          // MMK
  counterparty?: string,    // customer or supplier name (Burmese or English)
  product?: string,         // what was sold or bought
  quantity?: number,
  unit?: string,            // bags, pieces, viss, etc.
  occurredAt: timestamp,    // when it happened, not when logged
  confidence: number,       // 0..1
  rawExcerpt: string        // the words from the transcript that triggered this fact
}
```

**Example.** Owner says: *"ဒီနေ့ ဆန် ၂၀ အိတ်ရောင်းရတယ်။ ၁၂ သိန်း။ ဦးအောင်ကျော် ဆီ ၂ ပျား ဝယ်သွားတယ်၊ မပေးရသေးဘူး။"* (Today sold 20 bags of rice for 1.2M MMK. U Aung Kyaw took 2 viss of oil, hasn't paid yet.)

**Extracted facts:**
1. `sale` — amount 1,200,000 MMK, product "ဆန်" (rice), quantity 20, unit "အိတ်" (bag)
2. `sale` — counterparty "ဦးအောင်ကျော်" (U Aung Kyaw), product "ဆီ" (oil), quantity 2, unit "ပျား" (viss)
3. `payment_received` — counterparty "ဦးအောင်ကျော်", amount: null, status: "owed" → triggers a receivable

**Why voice first:** Typing Burmese on a phone is slow. Voice captures what's in the owner's head — the data no integration replaces.

### 2.2 Text input (manual entry and paste)

**Two flavors:**

- **Quick log** — Free-text box. Owner types or pastes anything in Burmese or English. Same extraction pipeline as voice. Example: paste a Viber message they received and let the system extract.

- **Structured sales entry** — Three-field form: amount (Arabic numerals), what was sold (optional Burmese text + autocomplete from existing products), customer (optional, autocomplete from existing entities). Fast path: three taps to log a sale. Skips extraction; writes a `sale` fact directly with confidence 1.0.

### 2.3 PDF ingest

**What the user does:** Shares a PDF to the app via system share sheet, or attaches one from Files/Drive.

**What gets handled:**
- **Digital PDFs** (invoices generated by accounting tools, supplier price lists): `pdf-parse` extracts text → fact extraction pipeline → confirmation.
- **Scanned PDFs**: Cloud Vision OCR with Burmese support → fact extraction. If OCR confidence is below threshold, owner sees the document with a "couldn't read this clearly — type the key bits in" fallback.

**Extracted facts from a typical invoice:** vendor name (becomes a supplier entity), date, line items (each becomes a `purchase` fact or `expense` fact), total amount.

### 2.4 Excel / spreadsheet ingest

**What the user does:** Shares an `.xlsx` or `.xls` file (their existing sales ledger, customer list, inventory sheet).

**What gets handled:** `xlsx` library parses the sheet. An LLM pass interprets the schema — Myanmar SME spreadsheets vary wildly (merged cells, headers offset by several rows, Burmese column names). The LLM identifies each column ("this is date, this is customer, this is amount in MMK, this is product").

**Confirmation step is mandatory.** Owner sees: "I think this spreadsheet has 47 sales records. Column A is date, column B is customer name, column C is amount. Is this right?" Owner can correct mappings before bulk import.

**Why this matters:** Many owners already keep records in Excel. Letting them bring that history in on day one means the home screen has real data immediately instead of waiting for weeks of voice notes.

### 2.5 Telegram bot

**Setup:** Owner messages `@LatticeMyanmarBot`, sends `/start`, gets a one-time 6-character code, enters that code in the mobile app's Profile screen to link.

**What gets handled:**
- **Forwarded text messages** (supplier price update, customer order via chat): extracted → bot replies with proposed facts and inline confirm/edit buttons.
- **Forwarded voice notes:** transcribed → extracted → same confirmation.
- **Forwarded photos and documents:** stored but not OCR'd in v1 (owner reviews in the mobile app).
- **Direct messages to the bot** ("ဒီနေ့ ဆန် ၁၀ အိတ်ရောင်းရတယ်"): same as quick-log via voice/text.

### 2.6 Viber

**Setup:** Owner long-presses a Viber message, taps "Share," selects Lattice from the share sheet.

**What gets handled:** The shared message arrives in the app, runs through extraction, owner confirms. Per-message basis (no API for full chat ingestion, unlike Telegram).

**Documented limitation:** Less convenient than Telegram. Owners are told this in the linking screen so they choose the channel they prefer.

### 2.7 What we do NOT ingest in v1

- Photo direct from camera (use voice + text instead; OCR on handwritten Burmese is unreliable)
- Email forwarding
- Browser extensions
- Direct accounting software integration (Tally, Vyapar — defer to v2)
- Bank SMS parsing
- WhatsApp (less dominant than Viber/Telegram in Myanmar)

## Part 3 — Fact-to-visual mapping

This is the most important section in the document. Each visual element on screen is fed by specific fact types. If those facts don't exist yet, the visual either shows an empty state with a call to input, or is hidden entirely until data exists.

### 3.1 The mapping table

| Visual element | Screen | Fed by fact types | Minimum data required | Empty state behavior |
|---|---|---|---|---|
| Hero metric (today/week/month sales) | Home | `sale` | 1 fact | Show "ဒီနေ့ ပြောစေချင်တယ်" (want to talk about today) with mic prompt |
| Sparkline (7-day trend of hero) | Home | `sale` (aggregated by day) | 3 days with at least one sale each | Hide until threshold met |
| Week strip (3 KPIs) | Home | varies by business type | 7 days of data | Show "—" for unfilled cells, with explanation tap |
| Top 3 products/customers | Home | `sale` with `product` or `counterparty` | 3 distinct products/customers in last 7 days | "Add product names when you log sales" hint |
| Attention card: customer-at-risk | Home | `sale` history per customer + `customer_absent` | 1 customer with 4+ historical orders | Hide |
| Attention card: cash-outstanding | Home | `sale` flagged owed + `payment_received` | 1 unpaid sale | Hide |
| Attention card: inventory-low | Home | `inventory_change` + `sale` | Manual setup of reorder thresholds | Hide until owner sets thresholds |
| Attention card: supplier-signal | Home | `supplier_signal` | 1 fact | Hide |
| Attention card: market-signal | Home | `market_signal` | 3+ mentions in 14 days | Hide |
| Revenue vs Target (bar chart, image 4 style) | Financial Report | `sale` + manually-set monthly target | 1 month of data + target | Show "Set a monthly target" CTA |
| Revenue trend (line chart) | Financial Report | `sale` (daily aggregate) | 14 days | Show progress bar "X days until trend chart unlocks" |
| Budget allocation (donut chart, image 4 style) | Financial Report | `expense` with categories | 5+ categorized expenses | "Log expenses to see breakdown" |
| Cash flow waterfall | Financial Report | `sale` + `payment_received` + `expense` | 30 days | Hide until threshold |
| Goal cards (image 6 style) | Goals & Budget | manually-set goals + tracked metrics | 1 goal created | "Set your first goal" prompt |
| Budget progress bars | Goals & Budget | manually-set budgets + `expense` | 1 budget created | "Set your first budget" prompt |
| Sales velocity projection (line chart, image 3 style) | Analytics | `sale` (daily) + Zep projection | 30 days | Show empty state with day counter |
| Market trend with projections (line chart, image 1 style) | Analytics | `sale` + `market_signal` + `supplier_signal` | 60 days | Hide; show "Analytics unlock after 2 months" |
| Customer acquisition channels (bar chart, image 2 style) | Analytics | `sale` with `acquisitionSource` tag | 10+ tagged customers | Show "Tag where customers come from to see this" |
| Customer segment alignment (bar chart, image 2 style) | Analytics | customer tags (SMB/Retail/Enterprise equivalent) | 10+ tagged customers | Show tagging CTA |
| Strategic KPI cards (image 5 style) | Analytics | aggregates from multiple fact types | 7 days | Show partial cards with "—" |
| Recent intelligence list (image 1 right panel) | Analytics | extracted facts from PDF/Excel/Telegram | 1 imported document | Hide |
| Sources list (per detail screen) | All detail screens | every fact has `sourceId` provenance | always present when a fact exists | n/a — sources are always available |

### 3.2 Progressive disclosure rules

The app must never look broken. Three rules:

1. **Day 1 to Day 3** — Only Home screen is populated. Other tabs show educational empty states explaining what unlocks them.
2. **Day 4 to Day 14** — Home is rich. Financial Report begins to populate. Goals & Budget shows if the owner has set anything. Analytics still mostly empty.
3. **Day 15 onward** — All screens are fillable. Analytics begins to show projections.

The "unlock counter" pattern (image 3 style — "X days until this chart appears") is used sparingly and only for charts that genuinely need time-series data. For charts that need user setup (targets, budgets, customer tags), use direct CTAs instead.

### 3.3 Data freshness

- Hero metric and attention cards: regenerated within 30 seconds of a new confirmed fact
- Financial Report charts: regenerated nightly + on-demand pull-to-refresh
- Analytics charts: regenerated nightly only (expensive to compute)

## Part 4 — Five-screen architecture

The dock has five primary tabs. The mic is the center action and is visually dominant.

```
[ Home ]  [ Reports ]  [ ● Mic ● ]  [ Analytics ]  [ Profile ]
```

**Customers/People is NOT a primary tab.** It lives as a tap-through from Home (tap a customer name in an attention card) and from Reports (a "Customers" sub-section). This keeps the dock at five items and respects the principle that the dock should answer "what do I want to look at" not "what data exists."

### 4.1 Screen 1 — Home (the briefing)

**Purpose:** Answer the four daily questions in 30 seconds.

**Vertical regions, top to bottom:**

1. **Header** — date in mono caps (`MON · 26 MAY`), Burmese greeting with owner name, notification bell with unread indicator. Profile avatar on far right (links to Profile tab).
2. **Hero pinned cards strip (image 6 inspiration)** — horizontal-scroll strip of 2–4 pinned KPI cards. Default first card is the hero metric (today's sales, full serif treatment). User can pin secondary cards: outstanding receivables, this week's profit, top customer this week. Each card has a small graphic icon (pinned icon top-right like image 6) and a sparkline ribbon at the bottom. Cards are 280×140 with the Plum gradient background; the first (active) card has more saturation, others muted.
3. **Sparkline detail** — Only appears when the user taps a pinned card to expand. Shows the 7-day shape with day markers and the trend pill.
4. **Week strip** — three secondary metrics in a horizontal grid between two hairline borders. Mono eyebrows, serif numbers.
5. **Top three** — ranked list of three top products or customers. Serif rank number, Burmese name, value, thin progress bar in plum opacity gradient.
6. **Needs attention** — 2–4 stacked cards with icon containers, Burmese headline, English subline, chevron-right. This is the attention queue.
7. **Recent activity (image 6 inspiration)** — 3–5 most recent confirmed facts as a vertical list. Each row: source icon (mic/text/telegram/PDF/Excel/Viber), one-line Burmese description, amount, time-ago. Tappable to source detail.
8. **Floating dock** — five tabs, center mic prominent.

### 4.2 Screen 2 — Reports (the financial report)

**Purpose:** "How is the business doing financially this month?"

**Inspired by image 6 middle screen + image 4 chart styles.**

**Vertical regions:**

1. **Header** — back chevron (returns to Home), title "Reports" in Burmese, download icon (export — defer to v1.1, render as placeholder).
2. **Hero gauge (image 6 middle screen inspiration)** — a half-circle radial gauge showing the current month's revenue vs. monthly target. Center label: the target amount. Tooltip on the dial: current revenue. If no target is set, show "Set a monthly target to see your progress."
3. **Period toggle** — Weekly / Monthly / Quarterly / Yearly pill row, monthly active by default.
4. **Revenue vs. Target bar chart (image 4 style)** — vertical bars showing past 6 periods. Active period highlighted with a tooltip showing exact numbers (full MMK format here). Plum for revenue, muted lavender for target.
5. **Budget allocation donut (image 4 right side)** — donut chart of expense categories for the selected period. Three to six segments max. Color-coded with the Plum palette plus accent variants.
6. **Recent transactions list (image 6 middle screen)** — 6–10 most recent expense and revenue items. Icon (source type or vendor logo if available), description, amount (negative for expense, positive for revenue), time-ago.
7. **Floating dock**.

### 4.3 Screen 3 — Goals & Budget

**Purpose:** "Am I on track for what I said I wanted?"

**Directly inspired by image 6 right screen.**

**Vertical regions:**

1. **Header** — title "ပန်းတိုင်နှင့် ဘတ်ဂျက်" (Goals & Budget).
2. **My Goals section** — stacked cards. Each card shows: a graphic icon (savings, expansion, debt payoff, new equipment), goal name in Burmese, current amount in serif with delta pill, target amount, progress bar in Plum gradient. "Add Goal" button at top right with a "+" icon. Tapping a card opens its detail screen with the contributing facts.
3. **Budgeting section** — stacked cards. Each card: category icon (coffee/fuel/rent/inventory), budget category name, spent-so-far in serif, "you have about X left" muted subline, progress bar that turns from plum to terracotta as it approaches/exceeds limit. "Add Budget" button at top right.
4. **Floating dock**.

**Why this screen exists:** MSME owners need a place to capture intent ("I want to buy a new fridge by August," "I want to keep food costs under 200K MMK/month"). Without it, the app only describes reality without helping shape it. This is where the temporal scenarios engine quietly works — goals and budgets are essentially branches in the system, but presented as concrete commitments rather than hypothetical futures.

### 4.4 Screen 4 — Analytics (the deep view)

**Purpose:** "What's happening that I might be missing?"

**Inspired by images 1, 2, 3, 5 — the strategic dashboard style.**

This is the most data-hungry screen. Most users won't see it fill up for 4–8 weeks. The empty-state design is critical.

**Vertical regions:**

1. **Header** — title "ထိုးထွင်းသိမြင်" (Insights / Analytics). Period toggle (Weekly / Monthly / Quarterly).
2. **Strategic KPI grid (image 5 style)** — 2×2 grid of cards. Each card: thin top accent bar in plum, mono eyebrow label, big serif number, small icon top-right, sparkline ribbon at bottom. Four default KPIs: Active Customers, Total Connections (suppliers + customers), Competitive Signals, Intelligence Sources.
3. **Sales velocity projection (image 3 style)** — line chart, last 30 days with dashed projection 30 days forward. Single-line "Sales" with a target dashed reference line if a target is set. Plum solid line, neutral dashed for target. Hidden until 30 days of data exists.
4. **Market trend analysis (image 1 style)** — multi-line chart showing competitor pressure, order volume, and active customers over 8 months with projected dashed extension. Plum, terracotta, sage. Includes monthly/quarterly toggle (image 1). Hidden until 60 days of data + at least one supplier or market signal extracted.
5. **Customer acquisition channels (image 2 left style)** — vertical bar chart. Channels: Walk-in, Telegram referral, Viber referral, Repeat. Hidden until customers are tagged with source.
6. **Customer segment alignment (image 2 right style)** — vertical bar chart. Segments: regulars, occasionals, one-timers. Computed automatically from order patterns once 30+ customers exist.
7. **Recent intelligence (image 1 right panel)** — list of recently ingested PDF/Excel/Telegram items that contained extracted facts. Each row: source icon, title or first line, source name, "N entities" pill.
8. **Floating dock**.

### 4.5 Screen 5 — Profile

**Purpose:** Settings, business profile, channel linking, account.

**Vertical regions:**

1. **Header** — avatar (large), business name, owner name. Tap to edit.
2. **Business profile section** — business type, hero metric choice, week strip configuration. Tap to edit.
3. **Channels section** — Telegram linking status with link/unlink button. Viber share instructions. PDF/Excel "what types are supported" reference.
4. **Goals & Budget shortcut** — quick link to that screen.
5. **Customers shortcut** — opens a sub-screen with all customer entities the system has identified.
6. **Suppliers shortcut** — opens a sub-screen with all supplier entities.
7. **Data & Privacy section** — export data (placeholder for v1.1), delete account.
8. **About section** — version, help, contact.
9. **Sign out**.

## Part 5 — Visual language — Plum Linen

A purple-cream palette inheriting structure from image 6, with the architectural restraint of the original Amber Luxe spec.

### 5.1 Palette

```
Backgrounds
  bg/base            #F8F4F1   warm cream, the canvas
  bg/surface         #FFFFFF   cards, raised elements
  bg/elevated        #F2EDE9   subtle inset, week strip
  bg/gradient-1      linear-gradient(135deg, #F0E6F0 0%, #F7E8E0 50%, #FCEEE0 100%)
                              the soft plum-to-peach gradient on pinned cards and the gauge
  bg/gradient-2      linear-gradient(180deg, #3A1A4A 0%, #2D1238 100%)
                              the deep plum used on the dock mic button only
  bg/icon-soft       #EDE4ED   icon containers for attention items (soft plum)
  bg/icon-neutral    #F0EAE6   icon containers for neutral items
  bg/track           #EDE4ED   progress bar tracks

Borders
  border/default     #E8E0DA   1px default
  border/hairline    rgba(0,0,0,0.05)

Text
  text/primary       #2A1F2D   deep plum-black, near-black, all primary text
  text/secondary     #7A6B7D   muted plum-brown, labels and metadata
  text/tertiary      #B5A8B8   tertiary, axis labels, rank numbers, hints
  text/on-dark       #F8F4F1   cream text on the dark dock mic

Accent
  accent             #6B2D7B   rich plum, the brand color
  accent-pressed     #4F1F5C   plum-pressed, accent text on cream
  accent-soft        rgba(107, 45, 123, 0.12)   accent fills, pills, active nav
  accent-glow        rgba(107, 45, 123, 0.30)   shadow under mic only

Chart palette (for multi-series charts)
  chart-1            #6B2D7B   plum (primary)
  chart-2            #B85C8E   dusty rose
  chart-3            #5C7B6B   sage green
  chart-4            #C97755   muted terracotta
  chart-5            #7A8FB8   dusty blue

Semantic — used sparingly
  positive           #5C7B6B   sage, positive deltas when accent inappropriate
  caution            #C97755   muted terracotta, warnings
  critical           #A33D5C   muted rose, true alerts only
```

**Discipline rules:**
- The plum accent appears on signals, never on chrome
- The gradient appears on pinned cards, the gauge, and nowhere else
- The dark plum (`bg/gradient-2`) appears on the mic button only
- Charts use the chart palette (not the accent) so the accent stays scarce
- Dark mode is reserved but not built in v1

### 5.2 Typography

Four font families:

- **Instrument Serif** — display numbers, hero metrics, all large numerical values, gauge labels, accent words like "MMK"
- **JetBrains Mono** — eyebrows in caps with 0.16–0.20em letter-spacing, dates, IDs
- **Inter** — body, labels, descriptions, all UI copy
- **Noto Sans Myanmar** — Burmese script (via @font-face, paired with Inter)

Type scale:

```
mono-eyebrow         9–10px / 1.0   500   uppercase, 0.20em letter-spacing
caption              11px / 1.4    400
body                 13px / 1.4    400
body-medium          13px / 1.4    500
title                14px / 1.3    500
subhead              18px / 1.3    500
gauge-label          14px serif    400   italic
serif-md             18px serif    400   top-three rank values
serif-lg             24px serif    400   week-strip numbers, goal current amounts
serif-xl             30px serif    400   pinned-card numbers
serif-display        52px serif    400   hero metric, gauge center
serif-unit           20px serif italic   "MMK" beside hero
```

Weights cap at 500. Serif used only via Instrument Serif. No mid-sentence bold.

### 5.3 Spacing and radius

- **Spacing scale:** 4, 8, 12, 16, 18, 22, 24, 28, 32 px. Section padding: 22 horizontal, 24 vertical between regions.
- **Radius:** 12px on icon containers, 16px on attention cards, 20px on pinned cards, 24px on goal/budget cards, 36px on device frame, 50px on floating dock, 24px on the gauge frame.

### 5.4 Motion

- Card tap: scale to 0.98 over 120ms, return on release
- Page transitions: 240ms ease-out slide
- Voice button press: scale to 0.94, pulse the plum-glow shadow
- Sparkline appearance: stroke-dasharray draw-on over 600ms ease-out, first load only
- Gauge fill: animated radial sweep over 800ms on Reports screen load
- Pinned card horizontal scroll: native momentum scroll, snap-to-card
- No spring physics, no bouncing, no rotation

### 5.5 The gradient discipline

The Plum-to-peach gradient is the most distinctive visual element. It appears:
- On the pinned hero cards (Home, top region)
- As background for the radial gauge (Reports, top region)
- On the goal card backgrounds (Goals & Budget) — muted version
- Nowhere else

Used outside these contexts, the gradient cheapens the product. Restrain it.

## Part 6 — Empty states and progressive disclosure

The app must read as confident on day one. Empty states are designed to invite action, not apologize.

### 6.1 Cold-start Home screen (day 0)

After onboarding, before any fact is logged:

- **Header:** date + "မင်္ဂလာပါ [name]"
- **Pinned cards strip:** ONE card with the cold-start hero. Plum gradient background, a large mic icon centered, Burmese copy "ဒီနေ့ ဘယ်လို ဖြစ်ပျက်ခဲ့လဲ ပြောပါ" (tell me what happened today). Tapping the card = tapping the mic in the dock.
- **Week strip:** Hidden entirely until 1 fact exists.
- **Top three:** Hidden until 3 distinct products/customers exist.
- **Attention:** Hidden until at least 1 attention card generated.
- **Recent activity:** Hidden until 1 fact exists.

### 6.2 Day 1 to Day 3

- Pinned cards strip: today's sales (real number), placeholder card "Pin another KPI" with a + icon
- Week strip: appears with whatever cells can fill, others show "—"
- Top three: appears if 3 distinct products/customers logged
- Attention: appears if data warrants
- Recent activity: appears, growing list

### 6.3 Other screens (Reports, Analytics, Goals)

Each shows an educational empty state with:
- A serif headline in Burmese
- One-sentence English-mono subline explaining what unlocks the screen
- A CTA button if there's a user action (e.g., "Set monthly target," "Log expenses")
- A muted illustration of the screen as it will eventually look (use a faded screenshot or wireframe)

Example for Reports empty state: "ဘဏ္ဍာရေး အစီရင်ခံစာ" headline, "Log sales and expenses for 14 days to unlock financial reports" subline, "Tell me about today" mic button CTA.

### 6.4 Per-chart empty states

Each chart on Reports and Analytics shows its own empty state with:
- A faded version of the chart shape it will eventually become
- A specific message: "30 days until sales velocity chart appears" or "Tag where customers come from to see this chart"
- The relevant CTA where action is possible

## Part 7 — Component specifications

Reusable components, named for use in code.

### 7.1 PinnedCard

- 280×140 (default size for horizontal-scroll strip)
- Gradient background (`bg/gradient-1`)
- Small "pin" icon top-right (Tabler `pin` outline)
- Mono eyebrow top-left
- Serif number (30px) centered or top-left
- Subline (11px Inter muted) below number
- Optional sparkline ribbon at bottom (24px tall)
- Tap to expand into detail
- Active state: full saturation, others 70% opacity

### 7.2 Eyebrow

- JetBrains Mono caps, 9–10px, 500 weight, 0.20em letter-spacing
- Always `text/secondary` color
- Used for section headers, card labels, chart titles

### 7.3 SerifMetric

- Instrument Serif, multiple size variants (md/lg/xl/display)
- Always `text/primary`
- Optional italic "MMK" or "lakhs" suffix (use `serif-unit`)
- Optional accent pill below for delta

### 7.4 AttentionCard

- White surface, 16px radius, 1px border
- Left icon container (38×38, 12px radius)
- Two-line text: Burmese headline (13px medium), English subline (11px tertiary)
- Right chevron (16px tertiary)
- Full-width tap target
- Categories with specific icon + container color (see Part 3 mapping)

### 7.5 RadialGauge

- 280×160 half-circle
- Plum gradient background within a 24px-radius rounded rectangle
- Center label: target amount (Instrument Serif 18px)
- Tooltip pin on the arc showing current value (small dark pill)
- Animated fill on screen load (800ms ease-out)
- Toggle below: "Net Worth" / "Spending" (image 6 inspiration) — for v1 use "Revenue" / "Expenses"

### 7.6 GoalCard

- White surface, 24px radius, 1px border
- Top row: icon container (40×40 with muted gradient), goal name in Burmese (14px medium)
- Middle row: current amount in serif-lg, delta pill in accent-soft
- Bottom: progress bar (Plum gradient), target amount on right
- Full-width tap target

### 7.7 BudgetCard

- White surface, 24px radius, 1px border
- Top row: icon container (smaller, 32×32), category name in Burmese (14px medium)
- Middle: current spent in serif-lg

## Part 8 — Copy and voice

### 8.1 Voice principles

Calm, direct, respectful, Burmese-primary. Avoid:
- English SaaS phrases
- Imperative commands
- Patronizing simplification

Prefer:
- Burmese formal-warm register
- Concrete numbers and names over abstractions
- Questions over commands

### 8.2 Currency display

- **Hero, pinned cards, week strip:** abbreviated (`850K MMK`, `8.5M MMK`, `1.2Cr MMK`)
- **Reports charts:** abbreviated on axis, full in tooltips (`850,000 MMK`)
- **Detail screens:** full numbers
- **Sentences:** match surrounding context

Thresholds:
```
< 1,000                1 — 999 MMK
1,000 — 99,999         1K — 99K MMK
100,000 — 999,999      100K — 999K MMK
1,000,000 — 9,999,999  1.0M — 9.9M MMK
≥ 10,000,000           1.0Cr MMK and up
```

### 8.3 Language strategy

Burmese primary for content. English used only for:
- Mono-style eyebrows (`TODAY`, `WEEK`, `NEEDS ATTENTION`, `REVENUE`, `BUDGET`)
- Currency unit (`MMK`)
- Day-of-week labels (`MON` / `SUN`)
- Chart axis labels where space is constrained

All other UI copy in Burmese.

### 8.4 Numerals

Arabic numerals everywhere. Per locked v1 decision.

## Part 9 — Accessibility and platform notes

### 9.1 Touch targets

Minimum 44×44 (iOS HIG) on all tappable elements. Dock items are 48×48; mic is 48×48 prominent.

### 9.2 Text scaling

The app respects iOS Dynamic Type and Android font scaling up to 200%. Layouts use flexible spacing, not fixed heights, so text expansion doesn't break the design.

### 9.3 Burmese script rendering

Test all screens on:
- iOS (uses system Burmese)
- Android (often needs embedded font)
- Older Android devices (Galaxy J-series, low-end Xiaomi) common in Myanmar

Embedded Noto Sans Myanmar is mandatory on Android to prevent tofu (□) characters.

### 9.4 Network

Assume 3G as the baseline. All screens render from cache first, fetch in background. Voice uploads chunked, retried on failure.

### 9.5 Offline

V1 is networked-only for writes. Reads come from local cache (last-known briefing). Voice notes queue locally and sync when network returns. Robust offline-first is v1.1.

## Part 10 — What this design rejects

- **No graph/network visualization view.** The temporal graph runs invisibly.
- **No git-branch metaphor on screen.** Scenarios surface only via "talk this through" chat (deferred to v1.1).
- **No dashboard grids of equal-weight tiles.** Every screen has a clear hierarchy.
- **No badges or unread counts as primary surface.** One small dot on the bell.
- **No "AI" branding visible.** The system "remembers" and "notices" things.
- **No emojis.** Tabler outline icons only.
- **No shadows except on the floating dock and the mic button.**
- **No multi-color rainbow palettes.** Plum + chart palette only; semantic colors used sparingly.
- **No photo input in v1.** Voice and text cover the same use case more reliably.
- **No Customers/People as a primary dock tab.** Lives under Home and Profile.
- **No infinite scroll on Home.** The home view is intentionally bounded — six regions, no more.

## Part 11 — The acid test

Four questions before shipping any change:

1. **Does this answer the four daily questions in under 30 seconds?** (Money? Who owes me? What's running low? What's about to bite me?)
2. **Could a 45-year-old shop owner with mixed English literacy use this?** If a screen requires reading English, redesign in Burmese.
3. **Does it feel like a business document, not a consumer wellness app?** Editorial typography, restrained palette, intentional whitespace.
4. **Is the mic button the unmistakable primary action everywhere?**
